## 3. 已完成的确定性优化

### 3.1 递归词法块与实体中心

- 不再只看中心词的直接修饰语，而是按token位置递归遍历原子ATT图。
- 完整保留`S级 → 风险交付项目`与`风险 → 交付项目`等不同层级。
- 可补足LTP漏挂的紧邻实体边界，例如`网上事故恢复 → 及时率`、
  `高危 → 网络变更操作`。
- 显式“的”左侧形成完整修饰块，例如
  `根因未定性的 → 二级事故`、`低风险的 → 网络质量比拼网络`。

### 3.2 并列属性传播

同一局部短语内的并列属性共享完整中心词，但不会把另一项并进中心：

```text
一级或二级网上事故
→ 一级 → 网上事故
→ 二级 → 网上事故

中风险或高风险的网络质量比拼网络
→ 中风险 → 网络质量比拼网络
→ 高风险 → 网络质量比拼网络
```

### 3.3 显式后置状态、原因与关联

新增结构通道处理：

```text
实体 + 存在 + 状态
实体 + 是由于/由 + 原因 + 导致的
实体 + 是有 + 状态 + 的
原因/关联 + 相关的 + 实体
```

只截取原句连续片段，并受标点、查询词和已删除维度位置约束。

### 3.4 查询控制词与错误中心

- `TOP3`、`前N`不再进入业务中心词：
  `交付风险项目的 → 原因`。
- `有、是、存在、发生、执行`等通用谓词不能作为ATT业务实体中心，
  同时也不能被第四阶段修复规则重新选为中心。
- 同中心、同片段存在包含关系时，保留信息更完整的修饰语，避免
  `未定性的`和`根因未定性的`同时重复输出。

## 5. 仍然保留的边界

### 5.1 `业务`作用域歧义

`业务`可能是查询范围，也可能属于`业务产品、业务EHS`等实体名称。
当前不使用“见到业务就删除”的黑名单，因此部分结果仍保留`业务的`。
这是有意的保守策略，应由后续Schema或LLM结合业务实体定义裁决。

### 5.2 原子回填不等于完整语义

未触发规则的记录仍回填去维度原子ATT。它们具有可审计性，但不能统一视为
完整业务定语。下游应区分规则合并结果和原子回填结果。

### 5.3 上下文实体与目标实体

一条问题同时出现上下文实体和被查询实体时，例如第299行，
确定性规则能恢复`有风险的 → 项目`，但上下文中的
`S级 → 交付项目`也可能继续保留。是否删除上下文关系需要查询焦点判断，
当前不通过硬规则裁决。

## 6. 结论

在不引入LLM的前提下，本轮已经解决当前最明确、可泛化的结构问题，并为
后续LLM保留了清晰边界：LLM只需处理作用域、查询焦点和业务Schema裁决，
不必重新完成基础句法提取。
