# 第4.1阶段：无 LLM 原子 ATT 合并实验

本阶段读取并复现第四阶段的“去除维度原子 ATT”，只使用确定性规则生成
完整关系候选，不调用 LLM，也不修改第四阶段结果。

合并分为三路：

1. 原子图连续合并：把 `A → B、B → C` 或连续的
   `A → C、B → C` 合成原句中的连续修饰片段；
2. SRL 动词定语合并：使用第四阶段已经高置信接受、且以“的”结尾的
   SRL 连续片段，并把“的”后的连续实体成分扩入中心词；
3. 属性—实体合并：把属性型修饰语与紧凑实体成分拆开，例如
   `高风险 → 操作、变更 → 操作` 可得到
   `高风险 → 变更操作`。

最后一列不会无条件汇总三路候选，而是自动接受：

- 第四阶段已经高置信接受的 SRL 完整动词定语；
- 属性修饰语指向连续完整实体的结果；
- 中心词为数量、次数、占比、比率、完成率等指标，且没有更高优先级
  结果、并且修饰片段不含“的”的原子图合并。

含“的”的动词性结构如果没有被 SRL 恢复成完整连续片段，不自动进入最后
结果，避免出现 `导致的事故 → 数` 这类缺少原因论元的半截关系。

如果某个问题没有触发任何合并，最后一列不会写成`无`，而是原样回填
`第四阶段去除维度原子ATT`。只有去维度原子结果本身也是空时才输出`无`。
最后一列只输出纯关系，不附带规则来源、置信度或解释文字。

当前全量中，145 个问题触发合并；未触发合并的问题里，191 个回填原子
ATT，53 个因为原子结果本身为空而保持`无`。

指向普通实体的纯原子图合并只保留在中间列观察，避免把
`交付 → 项目、EI → 项目` 错当成 `交付EI → 项目` 这样的业务定语。

所有合并必须满足：

- 修饰语和中心词都是原句连续片段；
- 不补词、不调序、不改写；
- 不能与上游已经删除的维度字符重叠；
- 结果只作为候选，不直接当作最终业务定语。

运行：

```bash
conda run -n minimind python \
  4.1.merge_atomic_modifier_relations/merge_atomic_modifier_relations.py
```

默认输出：

```text
4.1.merge_atomic_modifier_relations/original_question_merged_modifier_relations.md
```
