# 4. 原子 ATT 纠错与补召回

第四阶段的主目标是提高原子 `ATT` 的召回率和中心词挂接准确率：

```text
cws + pos + dep + sdp + srl
        +
局部句法修复
        +
词序、SDP 与 SRL 辅助证据
```

SDP 和 SRL 都是受约束的辅助证据，不会被整图直接复制到结果。

## 为什么需要第四阶段

第三阶段保存 LTP 的完整 DEP 事实和全部原始 `DEP-ATT`，不做 POS
删除。第四阶段重新运行同一模型的 `cws + pos + dep + sdp + srl`，
使用 POS、局部依存结构、词序、SDP 和 SRL 证据作出原子关系决策。
全量数据中，同一种短语会得到不一致的依存结果：

```text
高风险交付项目

正确：高风险 -[ATT]→ 项目
误标：高风险 -[ADV/VOB/FOB]→ 交付 -[ATT]→ 项目
```

此外还存在：

```text
中风险 -[ATT/RAD]→ 个 -[...]→ 项目
高风险 -[ATT]→ 地区部   # 修饰语反向跨过“的”
二级 -[COO]→ 一级 -[ATT]→ 事故
关闭 -[ATT]→ 管理 -[ATT]→ 升级单
```

因此第四阶段必须在保留直接 ATT 的同时，生成可解释的纠错候选。

## 原子 ATT 定义

主体仍是最小修饰成分到最小业务中心词的关系：

```text
高风险 → 项目
交付 → 项目
网络 → 质量
```

本阶段不重建：

```text
产品质量导致的 → 网上事故
```

为了避免业务含义在分词后丢失，结果额外保留两类“词法语义原子”：

```text
负 → 增长
未 → 关闭
不 → 健康
```

这些关系并非传统 DEP 的 `ATT` 标签，但对业务检索中的极性、状态和
复合词边界不可缺失。本阶段仍不会把整个后置状态改写成
`不健康 → 网络质量`。

## 当前修复规则

### 1. POS/词面筛选直接 DEP-ATT

POS 是第四阶段的一种判断证据。方向正常、通过 POS 和词面噪声过滤的
直接 ATT 以高置信保留：

```text
source=dep_att
confidence=high
```

### 2. 量词中心词提升

当内容修饰语被错误挂到 `q/m/r`，而量词或其谓词能够连接到同一短语中的
内容中心词时，跳过量词：

```text
中风险 → 个 → 项目
修复：中风险 → 项目
```

来源：

```text
quantity_head_lift
```

查询词和数量词本身仍然过滤。

### 3. 紧凑名词短语补边

对于不跨标点、不含“的”的紧凑名词短语，如果属性词被标成
`ADV/VOB/FOB`，但它所依附的动词本身 `ATT` 到名词，则补充属性词到名词
中心词的关系：

```text
高风险 -[ADV]→ 交付 -[ATT]→ 项目
修复：高风险 → 项目
```

指标中心词是“次数、数量、率”等时，属性词优先连接被名词化的事件：

```text
疲劳 -[ADV]→ 驾驶 -[ATT]→ 次数
修复：疲劳 → 驾驶
```

来源：

```text
compact_np
```

### 4. 并列定语传播

并列修饰语继承同组修饰语的中心词：

```text
二级 -[COO]→ 一级 -[ATT]→ 事故
修复：二级 → 事故
```

来源：

```text
coordination
```

### 5. 反向 ATT 修复

汉语定语通常位于中心词之前。修饰语位于中心词之后，尤其反向跨越“的”
时，原关系标记为异常，并尝试重挂到右侧同一短语的内容中心词：

```text
高风险 → 地区部   # 错误
高风险 → 项目     # 修复
```

来源：

```text
backward_att_repair
```

### 6. 显式“的”属性组补边

“的”前属性组没有形成任何右向 ATT 时，寻找“的”后名词短语根：

```text
中风险或高风险的网络质量比拼网络

中风险 → 网络
高风险 → 网络
```

来源：

```text
explicit_de_head
```

### 7. SRL 中心词提升

SRL 只在“显式的 + 目标论元”同时成立时帮助纠正过短中心词，或把
错误落在“数量、率”等指标词上的动词提升到指标内部事件：

```text
关闭 → 管理 → 升级单
SRL A1=管理升级单

修复：关闭 → 升级单

关闭 → 数量
SRL A1=管理升级数量

修复：关闭 → 升级
```

来源：

```text
srl_head_lift
```

SRL 不匹配时不删除直接 ATT。

### 8. SDP 特征补边

只接收满足左修饰、右中心、不跨标点或“的”等约束的
`FEAT/dFEAT`，用于补回 DEP 误标的定中关系：

```text
收入 → 完成率
预算 → 完成率
```

来源：`sdp_feature`。

### 9. 词法修饰与否定极性

结合相邻词序、DEP-ADV 和 SDP-MANN/mNEG，恢复：

```text
负 → 增长
及时 → 恢复
疲劳 → 驾驶
未 → 关闭
```

来源：`adjacent_lexical_modifier`、`semantic_polarity`。

### 10. FOB 名词化复合词

对于 DEP 将名词修饰误标为 `FOB` 的局部结构，沿名词化路径恢复：

```text
风险 → 项目
管理 → 升级单
网络 → 变更 → 操作
```

来源：`fob_nominal_compound`。

### 11. 缩写和编号复合词

不依赖业务词典，通过字符形态与紧凑结构恢复：

```text
P3 → 比拼 → 网络
FaceboY → 比拼 → 网络
EI → 项目
```

来源：`alphanumeric_compound`、`verbal_nominal_compound`、
`alphanumeric_head_lift`。

### 12. 位置词和局部错挂过滤

过滤 `项目 → 中`、`收入 → 同比` 等中心词不是业务实体的伪 ATT；
对“不满客户声音”使用否定、VOB 和局部词序重建：

```text
不 → 满
满 → 客户
客户 → 声音
```

### 13. 无连词 COO 复合词

相邻动词性内容词被错误标成 `COO`，且中间不存在“和、与、或、、”等
并列边界时，按词序恢复局部复合链：

```text
管理 -[ATT]→ 数量
升级 -[COO]→ 管理

修复：管理 → 升级 → 数量
```

来源：`unmarked_coordination_compound`。

### 14. SRL 核心论元内部结构

只有当相邻内容词属于同一个连续 SRL 核心论元，并且 DEP 将它们平行挂到
同一谓词时，才补充论元内部局部关系。存在、判断、比较和统计谓词均被
排除：

```text
运营商 → 服务 → 订货
网上 → 事故 → 恢复
```

来源：`srl_argument_compound`、`srl_nominalized_predicate`。

### 15. 局部中心词纠正

属性词跨过相邻动词性名词平行挂到动词性外层中心时，恢复最短路径；
显式“的”左侧修饰语越过实体挂到指标词时，只沿指标词已有的直接 ATT
子节点重挂：

```text
高风险 → 操作；变更 → 操作
修复：高风险 → 变更 → 操作

场景 → 数；项目 → 数
修复：场景 → 项目 → 数
```

来源：`local_attribute_head`、`explicit_de_metric_head`。

### 16. 紧凑动词性名词宾语

动词性名词及其右侧名词宾语位于同一 SRL 核心论元，且中间只有直接
ATT 修饰语时，保留名词化复合关系；跨“的”、连词、标点或论元边界时
不触发：

```text
中风险 / 交付 / EI / 项目

中风险 → 项目
交付 → 项目
EI → 项目
```

来源：`srl_verbal_nominal_object`、
`srl_attribute_entity_projection`。

## 置信度

- `high`：直接 DEP-ATT，或多个结构证据共同支持的确定性修复；
- `medium`：紧凑名词短语等局部结构修复，保留供后续语义阶段裁决；
- `low`：当前不自动进入第四阶段原子 ATT。

第四阶段保留每条修复的来源、原依存标签和原因，便于审计。

## 运行

```bash
conda run -n minimind python \
  "4.extract_atomic_modifier_relations/extract_atomic_modifier_relations.py" \
  "data/original_question.md" \
  "4.extract_atomic_modifier_relations/original_question_atomic_modifier_relations.md"
```

默认配置：

```text
模型：LTP/base2
共享词典：segmentation_words.txt
词频：freq=2
```

## 阶段边界

第四阶段仍然不做：

- 维度过滤；
- 完整定语合并与改写；
- 后置状态和后置原因转换；
- 业务 RAG 价值判断；
- 无约束复制 SDP/SDPG 整图；
- Schema 映射。

这些职责应留给后续语义阶段。
